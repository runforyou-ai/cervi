# 联系人资料与客户档案方案

日期：2026-09-26。

本文是路线图「客服运营与渠道 › 访客与客户信息」中「联系人资料与客户档案」（P2）的实施方案，覆盖 AI 抽取与网站签名身份带入；联系人字段、标签及其在 AI 上下文中的使用以代码为准。全部交付后删除本文和路线图中的对应条目。

## 1. 范围决定

- **档案只存长期属性。** 订单号、单次故障现象这类只属于某一次咨询的信息写在周期小结里，业务数据由 AI 通过 MCP 实时查询，都不写入档案。
- **每个值都记录来源，按来源决定能否覆盖。** 来源分为网站、客服、AI 三种：网站可以覆盖任何来源；客服可以覆盖 AI 写的值，写入后 AI 不再改动；AI 只能写入空值或覆盖自己之前写的值。客服清空字段或移除标签时删除记录，AI 之后可以重新写入。
- **AI 只抽取客户明确说出的信息。** 不推测，不从客服的话里反推；抽取不到时不写。
- **抽取在客服周期关闭后异步执行。** 接待过程中 AI 客服已经能读到本周期的完整对话，实时抽取没有额外价值，还会拉长接待时延。
- **联系方式仍用 `contact_methods`。** AI 抽取到的邮箱和电话作为联系方式写入。疑似重复联系人的提示属于「重复联系人」事项，不在本方案内。
- **字段按名称匹配，不另设字段标识。** 网站签名身份的 `attributes` 以字段名称为键；字段改名后网站需要同步调整。

## 2. AI 抽取与自动打标

### 2.1 数据模型

新增增量迁移：

| 表 | 新增列 | 说明 |
|---|---|---|
| `contact_fields` | `ai_instruction text NOT NULL DEFAULT ''` | AI 填写说明；为空表示 AI 不填写该字段 |
| `contact_tags` | `ai_instruction text NOT NULL DEFAULT ''` | AI 添加条件；为空表示只能由客服添加 |
| `contact_field_values`、`contact_tag_assignments` | `source_service_session_id uuid` | 来源为 AI 时，抽取所依据的客服周期 |

`source` 增加 `ai` 取值。

### 2.2 任务

周期关闭时，`MarkClosed` 在同一事务中除了投递小结任务，再投递 `contact.profile_extract` 任务。任务读取与小结相同的周期沟通记录；周期内客户没有发言时直接结束。

**字段与联系方式抽取**用小结模型，单次调用：

- 输入：设置了填写说明的字段定义（名称、类型、选项、填写说明）、联系人当前的取值及来源、当前联系方式、沟通记录。
- 输出：`{"fields":[{"name","value"}],"emails":[],"phones":[]}`，只包含本次沟通中客户明确说出、且与现有值不同的项。
- 指令要求只依据客户自己的发言，不推测，不采用客服复述中客户没有确认的内容；按字段类型输出，单选只能从选项中选。
- 写入时逐项校验：字段存在且仍设置了填写说明，值符合类型，现有取值的来源是空或 `ai`。邮箱和电话按 `contact_methods` 的规范化规则去重后追加；该类型还没有主要联系方式时，新写入的这条设为主要联系方式。
- 联系人显示名称为空、客户在对话中明确说出自己的称呼时，写入显示名称。

**标签判断**用判断模型：每个设置了添加条件且联系人尚未拥有的标签作为一道是非题，概率达到阈值时添加，来源记为 `ai`。AI 不移除标签。

两类判断在同一个任务中执行，结果在一个事务中写入，并触达会话以刷新客户端。企业没有配置小结模型或判断模型时跳过对应部分；两者都没有配置时不投递任务。任务失败按小结任务的重试次数重试，耗尽后只记日志，不影响周期状态。周期重开后再次关闭时重新抽取，以关闭时间判断任务是否仍对应最新一次关闭，逻辑与小结任务一致。

### 2.3 界面

- 「客服设置 › 客户资料」的字段与标签弹窗增加「AI 填写说明」「AI 添加条件」，帮助文案说明 AI 会在对话结束后根据客户说过的话填写；列表第二行显示「AI 自动填写」或条件摘要。
- 联系人详情和客服侧栏中，AI 写入的值旁显示 AI 图标，悬停提示「AI 根据某次对话填写」，点击跳到对应会话。

## 3. 网站签名身份带入

签名身份载荷新增可选的 `attributes` 对象和 `tags` 数组：

```json
{ "sub": "u_123", "name": "…", "email": "…", "attributes": { "套餐": "专业版", "公司": "Acme" }, "tags": ["VIP"] }
```

- `attributes` 按字段名称匹配，单选字段按选项名称匹配；未定义的字段、类型不符的值和不存在的标签忽略，不报错。
- 验签通过、访客会话建立或恢复时写入，来源为 `website`，覆盖其他来源。载荷中没有出现的字段和标签保持不变。
- `customeridentity.Claims` 增加 `Attributes` 和 `Tags`，写入逻辑放在 `actions/contactprofile`，由访客会话建立流程调用。
- 客户身份设置页的接入说明补充这两个声明的示例；联系人详情中网站带入的值提示「由网站登录信息同步」。

## 4. PR 拆分

| PR | 内容 | 验收 |
|---|---|---|
| AI 抽取与自动打标 | 增量迁移、`contact.profile_extract` 任务、设置项与来源展示 | 网站和 Telegram 上各完成一次对话，关闭后档案按客户说过的话自动填写、打标签；客服修改过的值不被覆盖 |
| 网站签名身份带入 | 签名载荷 `attributes`、`tags`，接入说明 | 登录用户的套餐等属性在首次对话前就出现在档案中，AI 客服据此答复 |

## 5. 暂不处理

| 事项 | 启动条件 |
|---|---|
| 字段手动排序 | 字段按创建顺序展示；出现需要调整展示顺序的反馈 |
| 接待中 AI 通过工具实时写档案 | 出现需要在同一周期内由后续环节（例如转人工后的真人）立即看到新信息的反馈 |
| 档案取值的变更历史 | 出现需要追查某个值何时被谁修改的需求 |
| 按字段筛选和排序联系人 | 出现按属性圈选客户的需求，与开放接口一并评估 |
| 公司（组织）档案 | 出现 B2B 客户需要按公司聚合联系人的需求 |
