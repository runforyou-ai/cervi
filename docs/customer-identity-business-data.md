# Cervi 客户身份与业务系统接入方案

状态：设计中  
日期：2026-09-23  
范围：AI 通过 MCP 以网站登录用户身份查询业务系统并作为回答依据，以及客户身份的后续事项  
关联：本文是 [Cervi 路线图](roadmap.md) 登记的独立方案，对应「客服运营与渠道」中的业务系统接入（P1），设计细节只保留在本文

本文是主要参考，不构成强制约束，实施中按更合适的做法调整并同步更新；已交付的部分以代码为准，全部交付后连同路线图中的对应条目一并删除。

## 目标

客户在企业网站登录后打开 Messenger，AI 员工能查询他自己的订单、账户等记录，并依据查询结果直接答复；查询失败或客户未登录时追问或转人工。客服接手时在侧栏看到 AI 查过的业务数据。

验收场景：

- 企业把内部订单系统包装成 MCP 服务，登录用户问「我的订单到哪了」，AI 调用查询工具取得该用户的订单并作答，全程不转人工。
- 登录用户没有订单时，AI 依据空结果答复「没有查到订单」，不转人工。
- 匿名访客问同样的问题，AI 通过 `ask_customer` 引导登录，或转人工。

## 现状

- 网站登录用户识别与访客上下文已交付：企业网站以企业级客户身份密钥签发 HS256 JWT，Messenger 验签后以 `web-user:<sub>` 渠道身份访问，联系人带企业用户编号（`sub`）；AI 客服上下文开头是系统提供的客户上下文消息，含是否已验证、名称与本次访问信息，不含企业用户编号与邮箱。
- MCP 服务配置、AI 员工绑定和运行时挂载工具已具备；运行时挂载服务发现到的全部工具，MCP 工具报错（`IsError`）时调用按失败返回。
- 客服场景使用严格依据策略：直接输出的正文必须取得依据，否则纠正一次后按 `insufficient_evidence` 转人工；`ask_customer`、转人工与结束会话不经过该门禁。依据来源只登记了知识检索。
- 客服侧栏的「业务」页签是占位。

## 业务系统查询作为回答依据

### 工具用途

- MCP 服务的每个工具由管理员标记用途：查询或操作；新发现的工具未标记。标记按「服务 + 工具名」保存，刷新工具目录后保留仍存在的工具的标记，工具改名视为新工具。
- 客服场景只挂载标记为查询的工具；操作与未标记的工具在客服场景不挂载，随「P1.5：服务端副作用、审批和恢复」开放。其他场景的挂载规则不变。
- 查询工具即客服场景的依据来源，不另设依据开关。标记为查询是管理员对只读性的承诺，运行时不校验工具实际行为。

### 依据判定

- 查询工具调用成功且未标记错误时，结果即依据，包括空列表、空对象等「没有记录」的结果；结果去除空白后为空、传输失败或 `IsError` 不构成依据。
- 查询工具使用独立的判定函数，不复用知识检索的判定。
- 大结果被截断或清理后，沿用现有规则：模型完整读回原始结果才构成依据。
- 需要客户补充信息时仍使用 `ask_customer`。

### 客户范围服务

- MCP 服务增加「按客户查询」开关，服务级生效；同一服务不能同时提供公开查询与客户数据查询，需要时拆成两个服务。
- 开启后，客服场景的运行建立该服务会话时，在每个 HTTP 请求上附加 `X-Cervi-Customer-Id`（签名身份的 `sub`），有邮箱时附加 `X-Cervi-Customer-Email`。客户头在建立会话时固定，本次运行内不变。
- 客户已验证的定义：当前客服周期的渠道身份外部编号为 `web-user:<sub>` 且联系人有企业用户编号，与客户上下文消息的判定一致。未验证时该服务的工具不挂载；场景规则告知 AI 客户尚未登录，涉及个人数据的问题通过 `ask_customer` 引导登录，或转人工，不直接输出正文。匿名期间开启的客服周期在客户登录后仍为匿名，始终不挂载客户范围工具。
- 连接测试与工具目录刷新不附加客户头；业务系统在没有客户头时须仍能返回工具目录。
- 业务系统须以请求头确定数据范围：忽略工具参数中的客户编号，并校验订单号等资源属于该客户。邮箱头只作参考，不能作为授权依据。Cervi 以 MCP 认证令牌向业务系统证明调用方，不保证业务系统内的数据隔离。
- 设置页在开关旁用一行帮助文案说明请求头名称与业务系统须遵守的规则。

### 客服侧栏「业务」页签

- 列出当前客服周期内客服 AI 运行调用查询工具的全部记录：工具名称、查询参数、结果与时间，标出构成依据的调用，失败的调用展示失败说明；按时间倒序。不包含客服侧 AI 助手的运行。
- 数据来自运行过程记录，不另存副本：运行进入终态后才可见，保留期与运行过程记录一致。
- 过程记录中被截断的大结果只展示已记录的预览并标注已截断；JSON 结果格式化展示，超过展示上限时折叠。

## 暂不包含

- 匿名身份并入登录用户：客户登录前以匿名身份发起的会话不并入，出现客户反馈登录后找不到会话时再设计。
- Telegram 等其他渠道的客户身份验证：出现需求时按渠道单独设计，复用企业级客户身份密钥与企业用户编号。
- 客服在侧栏主动调用业务系统。
- 按 IP 解析地区的内置地理库：访客地区只取部署配置的可信代理国家头。
- 客户身份密钥轮换重叠期：重新生成密钥立即生效，出现网站无法接受身份中断的反馈时增加。
- 客户身份密钥的查看权限：角色权限建设前任何成员都能查看密钥，随角色权限统一收口。
