# Cervi 助理与桌面端本地运行实施方案

状态：实施中  
日期：2026-09-21  
范围：助理（成员本人创建、绑定自己电脑的 AI）的产品形态、交互与桌面端本地运行（P4）  
关联：本文是 [Cervi 路线图](roadmap.md) 登记的独立方案，设计细节只保留在本文；助理与 AI 员工在工作台中的展示位置见 [工作台信息架构与服务对象扩展方案](workbench-ia.md)

成员在自己的电脑上创建助理，助理在这台电脑上读写代码、执行命令和操作界面。主人可以和助理单聊，也可以把助理带进群里，让同事使用；助理对主人电脑的每一次改动都由主人审批。本文是主要参考，不构成强制约束，实施中按更合适的做法调整并同步更新；已交付的部分以代码为准，本文只保留后续批次的设计，全部交付后连同路线图中的对应条目一并删除。

## 产品定义

### 两类 AI

| | AI 员工 | 助理 |
| --- | --- | --- |
| 归属 | 企业，由管理员创建 | 成员本人创建，一个成员可以有多个 |
| 执行位置 | 服务端 | 只在主人绑定的那台电脑上 |
| 操作电脑 | 不能 | 能，限于主人为会话指定的工作区 |
| 模型 | 企业模型服务 | 企业模型服务；后续增加「本机 Agent」来源 |
| 在线 | 始终可用 | 绑定的电脑在线且未暂停 |
| 服务会话 | 可以接待客户、员工、伙伴 | 不能接待，与助理的对话不产生服务周期 |
| 内部单聊与群聊 | 可以 | 只进入主人所在的会话 |
| 通讯录 | 不列入；服务对象含本企业员工的以服务台列在同事中 | 挂在主人名下展示 |

执行位置由归属决定：AI 员工永远在服务端执行，助理永远在主人的电脑上执行。同一个 AI 不会因为触发者或会话不同而切换模型或执行位置。

### 命名

界面统一称「助理」，展示为「<主人姓名>的助理 · <助理名称>」，例如「张三的助理 · 小码」。英文界面使用 `Assistant`。

### 助理跟随主人

助理在主人的电脑上执行、动的是主人的文件、由主人审批，因此：

- 助理只出现在主人所在的会话中。其他成员不能与别人的助理单聊，只能在主人也在的群里使用它。
- 主人退出群聊时，其名下助理同时退出该群。
- 主人被停用时，其名下助理全部停用并退出所有群聊；主人恢复后助理保持停用，由主人重新启用。
- 助理不能接待客户，也不能被加入客户会话。

成员都可以创建助理，企业不设总开关；管理员可以停用单个助理。

## 交互

### 创建、管理与在线状态

助理的创建、编辑、换电脑、暂停、停用与在线状态已在桌面端和 Web 端上线，剩余：

- 移动端通讯录的「我的助理」列表与详情。
- 头像上的在线状态标记：在线绿点、离线灰色、暂停标记；目前在线状态以文字展示在列表与会话头。
- 编辑页的「审批」页签，随「写入、命令与审批」批次交付。

### 单聊

- 在绑定电脑上实时展示运行过程；其他端展示运行状态与最终回复。

### 群聊

- 群成员选择器中，助理列在主人下方；主人不在群内时看不到其助理。
- 主人拉入自己的助理时直接加入，同时为该群选择工作区。
- 其他成员拉入时向主人发出邀请，群内显示「等待 <主人> 同意」。主人在邀请卡片上选择工作区后同意，或拒绝；拒绝后群内显示结果。
- 选择工作区时列出当前群成员，并提示「群成员都能看到助理在这个工作区中读取的内容」。之后群内新增成员时，给主人一条提示。
- @ 助理与 @ AI 员工交互一致。助理之间、助理与 AI 员工之间按现有轮次规则接力，各助理在各自主人的电脑上执行。
- 主人可以随时把自己的助理移出任何群，群主可以移出群内任何助理。

### 审批

每个助理有一张审批规则，在编辑页「审批」页签配置：

| 触发者 | 读取文件 | 写入文件 | 执行命令 |
| --- | --- | --- | --- |
| 主人 | 自动允许（可改为每次确认） | 每次确认（可改为自动允许） | 每次确认（可改为自动允许） |
| 其他成员 | 每次确认（可改为自动允许） | 每次确认（固定） | 每次确认（固定） |

界面操作沿用命令执行的规则。

- 审批只在绑定电脑上处理：桌面端发系统通知，点击打开对应会话；运行过程中出现审批卡片，标明触发者（「<成员>请求」）、助理、工作区和完整命令或目标路径。
- 卡片操作为「允许」「本会话允许此命令」「拒绝」，拒绝可以填写原因。拒绝原因作为工具错误交回模型，模型可以换方案重试。「本会话允许此命令」按规范化参数哈希命中，只对主人本人触发的运行生效。
- 群内其他成员在助理的发言位置看到「等待 <主人> 确认」，不展示命令细节。
- 其他成员触发的审批 10 分钟内未处理时，本次运行结束，助理回复「<主人>没有确认，未执行」。主人本人触发的审批不设超时。
- 主人的工作状态为「离开」或「下班」时，其他成员触发的写入与命令立即失败，助理回复「<主人>当前不在，无法确认」；读取按规则执行。
- 一个运行认领的输入窗口内混有主人与其他成员的触发时，按其他成员的规则执行。运行不得通过吸收新输入扩大能力；新输入会降低能力时，运行停在当前边界不吸收，交给下一个运行处理。

### 各端差异

| | 绑定电脑上的桌面端 | 其他桌面端 | Web 与移动端 |
| --- | --- | --- | --- |
| 创建、换电脑 | 可以 | 可以（换到这台电脑） | 不可以 |
| 与助理对话 | 可以 | 可以 | 可以 |
| 审批 | 可以 | 不可以 | 不可以 |
| 运行过程 | 实时流式 | 状态与最终回复 | 状态与最终回复 |

## 架构

```text
服务端
├── 发送事务与群聊轮转：助理的 Run 写入执行设备（助理绑定电脑）与该会话的工作区，不投递服务端任务
├── 设备工作通知：提交后经成员事件流推送 device_work_advanced
├── 领取与续租：设备领取 Run 并取得租约，续租响应回带取消状态
├── 运行期服务：Peek／Claim 读取 Lane 输入、知识检索、附件读取、审批状态上报
├── 模型代理：校验 Run、设备与租约后注入供应商凭据并透传流式响应
└── 收尾：result 与 failure 两个入口进入既有结果事务，群聊在同一事务提取点名并轮转

桌面端 Go
├── 设备注册与领取循环：独立定时器加事件流唤醒
├── agentruntime：与服务端同一份代码
├── 远程适配器：InputFeed、知识检索、附件读取、模型 BaseURL 指向服务端代理
├── 本机工具：workspaceBackend 实现 filesystem.Backend，workspaceShell 实现 filesystem.Shell
├── 审批中间件：按助理审批规则与触发者拦截工具调用，经 Wails 事件请求本机确认
└── 本机运行流：本机界面查看本机执行中的运行时直接订阅本机过程流
```

## 不变量

- **执行位置由归属决定。** AI 员工的 Run 只在服务端执行，助理的 Run 只派发到助理绑定的电脑。
- **运行时同一份。** 服务端与设备执行同一份 `internal/integration/agentruntime` 代码，有效配置由同一个解析器 `ResolveAssignment` 产出。执行侧能力只影响工具清单、指令中的工具说明和 MCP 服务名称。
- **业务事实只在服务端。** Run、Lane、Input、内容块、结果消息幂等和群聊轮转全部在服务端事务内完成，设备本地只保存设备注册、工作区路径和会话内命令许可。
- **企业凭据不下发。** 使用企业模型服务时，设备取得的配置不含模型凭据，模型调用经服务端代理。
- **路径不上行。** 工作区真实路径只存在设备本地数据库，服务端只保存工作区编号与显示名。
- **助理跟随主人。** 助理只作为参与者存在于主人所在的会话，主人离开即随之离开。
- **能力按交集。** 有效工具集是助理配置、会话工作区指定、设备能力清单和触发者审批规则的交集；任一侧出现对方不认识的能力名一律丢弃。
- **有意终止是终局。** 停止、审批超时和租约过期后的 Run 不自动续跑，本机命令可能已产生副作用。

## 数据模型

- 审批规则写入 `agent_revisions.configuration`，修改规则生成新配置版本，Run 的行为快照记录生效的规则。
- 其他成员发起的邀请由新表 `conversation_assistant_invitations` 表达：`organization_id`、`conversation_id`、`agent_id`、`invited_by_user_id`、时间戳，`(organization_id, conversation_id, agent_id)` 唯一。主人同意时在同一事务中加入参与者、写入工作区并删除邀请；拒绝时删除邀请并写入群系统消息。
- `devices` 的 `runtime_version` 与 `tool_manifest jsonb` 随只读本机工具批增加；`trust_level` 与服务端 Agent 调用设备用的 `capability_manifest` 随 P2 增加。

`DeviceRunBackend` 增加：

| --- | --- |
| `PUT /agent-runs/:runID/approval` | 上报或清除等待主人确认的状态，推进会话版本，供群内展示「等待确认」 |

`Backend` 增加群聊邀请的发起与处理。

## 派发与租约

- 本机前端对被同一工作区挡回的领取展示「等待同一工作区的其他任务完成」。
- 停止、审批超时与租约失效时，除中断 Agent 循环外还要终止该 Run 启动的整个命令进程组。

## 运行时对齐

- 行为快照在领取时写入，工具清单取决于领取设备的能力清单与该会话的工作区指定；快照写定后，重试落在不再提供这些工具的设备上时直接失败。
- 首版不加载配置版本绑定的企业远程 MCP 服务。

## 本机工具

首批工具由 `adk/middlewares/filesystem` 提供定义、提示词和大结果转存，Cervi 只实现两个接口。官方只提供内存后端，本地磁盘后端自行实现。

`workspaceBackend` 实现 `filesystem.Backend`：

- 所有路径先相对工作区根规范化，再经 `filepath.EvalSymlinks` 解析，解析后仍必须位于工作区内，`..` 或符号链接越出工作区的路径被拒绝。
- `GrepRaw` 用 Go 正则实现，工具描述改写为实际支持的语法，描述与实现保持一致。
- 实现 `MultiModalReader`，支持读取图片与 PDF。

`workspaceShell` 实现 `filesystem.Shell`：

- 工作目录固定为工作区根，以独立进程组启动。超时、取消和 Run 结束三条路径都终止整个进程组。
- 输出按字节上限裁剪并置 `Truncated`；命令预算由后端自己计时并置 `TimedOut`。
- 环境变量按白名单传递，不透传桌面进程的完整环境。
- 首版只在 macOS 与 Linux 注册命令执行工具；Windows 只提供文件工具，界面说明原因。

五个超时各自命名，互不复用：设备租约续期间隔、本地 Run 总时限、单次命令预算、单轮模型静默、其他成员触发的审批等待（10 分钟）。

### 能力组与风险类别

能力在审批规则上按组表达，单个工具映射进组。已有组内增加工具不改配置与界面。

| 能力组 | 工具 | 风险类别 |
| --- | --- | --- |
| 文件读取 | `ls`、`read_file`、`glob`、`grep` | 只读 |
| 文件写入 | `write_file`、`edit_file` | 改本机状态 |
| 命令执行 | `execute` | 执行任意代码 |
| 界面操作 | 截图、鼠标与键盘输入 | 操作界面 |

每个工具携带声明的风险类别，审批中间件按类别与触发者查审批规则，**没有声明类别的工具默认需要审批**。注册表覆盖测试断言每个工具都有类别，且其他成员触发的非只读工具都会触发审批。

### 工具扩展规则

- 设备在注册和启动时上报 `tool_manifest`，服务端按交集计算有效集，两侧未知的能力名一律丢弃。
- 服务端可为工具声明所需的最低设备运行时版本，低版本设备直接得不到该工具，不产生业务兼容分支。
- 审批中间件必须同时实现 `WrapInvokableToolCall` 和 `WrapEnhancedInvokableToolCall`。返回多模态结果的工具走 Enhanced 路径，只实现前者会让这类工具经基类直通默认实现而不触发审批。
- 启用后台命令时，后台任务生命周期绑定在 Run 上，Run 结束即终止。
- 工具总数使上下文中的工具定义成为负担时，改用 `adk/middlewares/dynamictool/toolsearch` 按需暴露。

## 审批实现

- 审批中间件在工具执行前发 Wails 事件并阻塞等待本机确认；运行时与界面同进程，不需要 CheckpointStore 与中断恢复。
- 等待其他成员触发的审批时，设备经 `approval` 路由上报等待状态，确认、拒绝或超时后清除。
- 审批决定、触发者、审批人、工具参数、参数哈希和裁剪后的结果写入 Run 内容块，随收尾回写服务端审计。

## 安全边界

- 首版不提供操作系统级沙箱，命令执行以主人逐次审批和工作区围栏为防线，残余风险明确承认。
- 设备认证是登录 Token 加设备编号加撤销位，挡不住 Token 泄露后的设备冒用。后续强化路径是设备密钥对与请求签名。
- 其他成员可以通过对话诱导助理读取并在群内输出工作区内容，因此其他成员触发的读取默认每次确认，主人选择工作区时明示群成员范围。
- 引入跨 Run 长期记忆时，每条记忆必须携带来源受众标签，只返回给同受众的运行。

## 本机 Agent 模型来源（后续）

助理增加「本机 Agent」作为模型来源：助理背后是主人电脑上安装的外部编程 Agent（如 Codex CLI、Gemini CLI），经 ACP 驱动，由外部 Agent 使用其官方登录与主人的订阅额度。

- 订阅凭据只由外部 Agent 自己管理，Cervi 不读取、不保存、不上传。
- 此来源的助理不走 `agentruntime`：Cervi 负责把会话输入交给外部 Agent、转发其权限请求到审批卡片、回写最终回复与过程摘要，输入认领、结果事务与群聊轮转仍在服务端。
- 各外部 Agent 的订阅是否允许经第三方客户端驱动，接入前逐个核实条款。
- 启动条件：内置运行时的助理交付后，出现使用个人订阅的真实需求。

## 交付批次

**只读本机工具。** `workspaceBackend`、工作区身份校验、路径围栏、能力清单上报与交集。验收：`..`、符号链接、已移动的工作区全部被拒；低版本设备得不到未支持的工具。

**写入、命令与审批。** `workspaceShell`、进程组终止、审批规则与编辑页「审批」页签、审批中间件两条路径、会话内命令许可、决定入块。验收：拒绝后模型能改方案重试；停止时命令进程组终止；多模态结果工具同样触发审批。

**群聊中的助理。** 建群与拉人选择器列出本人助理并在加入时选择工作区、群内的助理工作区入口、群内展示「<主人>的助理 · <名称>」、邀请与同意、群内工作区指定与成员范围提示、其他成员触发的审批规则、等待确认状态上报与展示、审批超时、工作状态联动、群主移出助理。验收：其他成员触发的写入与命令必须主人确认；主人离开或下班时立即失败；超时后运行结束且不续跑。

**界面操作。** 截图、鼠标与键盘输入，随 macOS 辅助功能与屏幕录制授权引导一起交付。

## 验收边界

- AI 员工只在服务端执行，助理只在绑定电脑上执行。
- 助理不出现在主人不在的会话和任何客户会话中。
- 停止与审批超时后本机命令进程组终止。
- 设备侧不出现企业模型供应商凭据，服务端不出现工作区真实路径。
- 工作区外路径被拒绝。
- 其他成员触发的写入、命令与界面操作一律需要主人确认。
- 设备撤销后不能调用模型代理。
- 服务端与设备对同一 Run 解析出同一份有效配置。
- 未声明风险类别的工具不会被自动放行。

## 不做的事

操作系统级沙箱、外部编辑器经 ACP 调用 Cervi、移动端本地运行、设备端本地模型与离线运行、跨设备迁移进行中的 Run、移动端与 Web 端审批、远程指挥不在场的电脑、设备侧本地知识库。

## 未决

- 设备侧运行时崩溃与桌面端主进程崩溃的区分上报方式。
- Windows 命令执行的进程组方案与开启条件。
- 附件在设备与模型代理之间的二次搬运是否需要由代理直接注入。
