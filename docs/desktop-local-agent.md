# Cervi 助理与桌面端本地运行实施方案

状态：实施中  
日期：2026-09-23  
范围：助理（成员本人创建、绑定自己电脑的 AI）的产品形态、交互与桌面端本地运行（P4）  
关联：本文是 [Cervi 路线图](roadmap.md) 登记的独立方案，设计细节只保留在本文；助理与 AI 员工在工作台中的展示位置见 [工作台信息架构与服务对象扩展方案](workbench-ia.md)

成员在自己的电脑上创建助理，助理在这台电脑上读写代码和执行命令。助理可以使用企业模型服务，也可以接入主人电脑上已安装的编程 Agent（如 Codex、Claude Code）。主人可以在任意端和助理对话并审批它对电脑的改动；把助理带进群里后，同事可以让它查阅主人授权的工作区，写入与命令只由主人触发。本文是主要参考，不构成强制约束，实施中按更合适的做法调整并同步更新；已交付的部分以代码为准，本文只保留后续批次的设计，全部交付后连同路线图中的对应条目一并删除。

## 产品定义

### 定位

Cervi 不重做编程 Agent。助理的价值是把本机 Agent 放进协作会话：任务从聊天发起，过程和结果留在会话里，同事可以在群里共用主人授权的上下文。

- 主人电脑上已有编程 Agent 与个人订阅时，助理以「本机 Agent」为来源，由外部 Agent 完成工作。
- 没有个人订阅或需要使用企业模型时，助理使用内置运行时与企业模型服务。

### 两类 AI

| | AI 员工 | 助理 |
| --- | --- | --- |
| 归属 | 企业，由管理员创建 | 成员本人创建，一个成员可以有多个 |
| 执行位置 | 服务端 | 只在主人绑定的那台电脑上 |
| 操作电脑 | 不能 | 能，限于主人为会话指定的工作区 |
| 模型 | 企业模型服务 | 企业模型服务，或主人电脑上的本机 Agent |
| 在线 | 始终可用 | 绑定的电脑在线且未暂停 |
| 服务会话 | 可以接待客户、员工、伙伴 | 不能接待，与助理的对话不产生服务周期 |
| 内部单聊与群聊 | 可以 | 只进入主人所在的会话 |
| 通讯录 | 企业通讯录成员 | 挂在主人名下展示 |

执行位置由归属决定：AI 员工永远在服务端执行，助理永远在主人的电脑上执行。同一个 AI 不会因为触发者或会话不同而切换模型来源或执行位置。

### 命名

界面统一称「助理」，展示为「<主人姓名>的助理 · <助理名称>」，例如「张三的助理 · 小码」。英文界面使用 `Assistant`。

### 助理跟随主人

助理在主人的电脑上执行、动的是主人的文件，因此：

- 助理只出现在主人所在的会话中。其他成员不能与别人的助理单聊，只能在主人也在的群里使用它。
- 只有主人能把自己的助理加入群聊。
- 主人退出群聊时，其名下助理同时退出该群。
- 主人被停用时，其名下助理全部停用并退出所有群聊；主人恢复后助理保持停用，由主人重新启用。
- 助理不能接待客户，也不能被加入客户会话。

成员都可以创建助理，企业不设总开关；管理员可以停用单个助理。

## 交互

### 创建、管理与在线状态

助理的创建、编辑、换电脑、暂停、停用与在线状态已在桌面端和 Web 端上线，剩余：

- 移动端通讯录的「我的助理」列表与详情。
- 头像上的在线状态标记：在线绿点、离线灰色、暂停标记；目前在线状态以文字展示在列表与会话头。
- 编辑页的模型来源选择：企业模型服务或本机 Agent，随「审批与本机 Agent」批次交付。

### 单聊

- 在绑定电脑上实时展示运行过程；其他端展示运行状态与最终回复。
- 运行改动了工作区时，最终回复附带变更摘要：改动的文件列表与各自的增删行数。在绑定电脑上可以查看每个文件的差异。

### 群聊

- 群成员选择器中，主人能看到并添加自己的助理；其他成员看不到别人的助理。
- 主人添加助理时为该群选择工作区。选择界面列出当前群成员，并提示「群成员都能看到助理在这个工作区中读取的内容」；主人确认即授权群成员让助理读取该工作区。之后群内新增成员时，给主人一条提示。
- @ 助理与 @ AI 员工交互一致。助理之间、助理与 AI 员工之间按现有轮次规则接力，各助理在各自主人的电脑上执行。
- 其他成员触发的运行只提供只读工具，读取直接执行；需要改动文件或执行命令时，助理回复需由主人发起。
- 主人触发的运行按该会话的审批模式执行。
- 主人可以随时把自己的助理移出任何群，群主可以移出群内任何助理。

### 审批

主人为每个「会话 × 助理」选择一种审批模式，与工作区一起在会话中设置：

| 模式 | 读取 | 写入 | 执行命令 |
| --- | --- | --- | --- |
| 只读 | 自动 | 不提供 | 不提供 |
| 自动编辑（默认） | 自动 | 自动 | 每次确认 |
| 完全自动 | 自动 | 自动 | 自动 |

- 审批模式只对主人触发的运行生效；其他成员触发的运行固定为只读。
- 审批卡片标明助理、工作区和完整命令或工作区内的相对路径，操作为「允许」「允许此类命令」「拒绝」，拒绝可以填写原因。拒绝原因作为工具错误交回模型，模型可以换方案重试。
- 「允许此类命令」把命令前缀加入该会话的允许列表，之后以该前缀开头的命令自动执行。允许列表只匹配单条命令，含管道、重定向或命令串联的命令仍需确认。
- 主人可以在任意已登录的端处理审批：待确认请求推送到主人所有在线端，桌面端发系统通知，点击打开对应会话。
- 群内其他成员在助理的发言位置看到「等待 <主人> 确认」，不展示命令细节。
- 一个运行认领的输入窗口内混有其他成员的触发时，本次运行固定为只读。运行不得通过吸收新输入扩大能力；新输入会降低能力时，运行停在当前边界不吸收，交给下一个运行处理。

### 各端差异

| | 绑定电脑上的桌面端 | 其他桌面端 | Web 与移动端 |
| --- | --- | --- | --- |
| 创建、换电脑 | 可以 | 可以（换到这台电脑） | 不可以 |
| 与助理对话 | 可以 | 可以 | 可以 |
| 审批 | 可以 | 可以 | 可以 |
| 运行过程 | 实时流式 | 状态与最终回复 | 状态与最终回复 |
| 查看文件差异 | 可以 | 不可以 | 不可以 |

## 架构

```text
服务端
├── 发送事务与群聊轮转：助理的 Run 写入执行设备（助理绑定电脑）与该会话的工作区，不投递服务端任务
├── 设备工作通知：提交后经成员事件流推送 device_work_advanced
├── 领取与续租：设备领取 Run 并取得租约，续租响应回带取消状态
├── 运行期服务：Peek／Claim 读取 Lane 输入、知识检索、附件读取
├── 审批：记录设备上报的待确认请求，推送到主人所有在线端，接收主人的决定并唤醒设备
├── 模型代理：校验 Run、设备与租约后注入供应商凭据并透传流式响应
└── 收尾：result 与 failure 两个入口进入既有结果事务，群聊在同一事务提取点名并轮转

桌面端 Go
├── 设备注册与领取循环：独立定时器加事件流唤醒
├── agentruntime：与服务端同一份代码，用于企业模型服务来源
├── ACP 适配器：驱动本机外部 Agent，用于本机 Agent 来源
├── 远程适配器：InputFeed、知识检索、附件读取、模型 BaseURL 指向服务端代理
├── 本机工具：workspaceBackend 实现 filesystem.Backend，workspaceShell 实现 filesystem.Shell
├── 审批中间件：按会话审批模式与触发者拦截工具调用，向服务端上报待确认请求并等待决定
├── 变更摘要：按本次运行的写入与编辑汇总改动文件和增删行数，随结果提交
└── 本机运行流：本机界面查看本机执行中的运行时直接订阅本机过程流
```

## 不变量

- **执行位置由归属决定。** AI 员工的 Run 只在服务端执行，助理的 Run 只派发到助理绑定的电脑。
- **运行时同一份。** 企业模型服务来源的助理与服务端执行同一份 `internal/integration/agentruntime` 代码，有效配置由同一个解析器 `ResolveAssignment` 产出。执行侧能力只影响工具清单、指令中的工具说明和 MCP 服务名称。
- **业务事实只在服务端。** Run、Lane、Input、内容块、审批记录、结果消息幂等和群聊轮转全部在服务端事务内完成，设备本地只保存设备注册和工作区路径。
- **企业凭据不下发。** 使用企业模型服务时，设备取得的配置不含模型凭据，模型调用经服务端代理。
- **订阅凭据不上行。** 本机 Agent 来源的登录与订阅凭据只由外部 Agent 自己管理，Cervi 不读取、不保存、不上传。
- **路径不上行。** 工作区真实路径只存在设备本地数据库，服务端只保存工作区编号与显示名；审批请求与变更摘要只上报工作区内的相对路径。
- **助理跟随主人。** 助理只作为参与者存在于主人所在的会话，主人离开即随之离开。
- **能力按交集。** 有效工具集是助理配置、会话审批模式、设备能力清单和触发者的交集；其他成员触发时只剩只读工具；任一侧出现对方不认识的能力名一律丢弃。
- **有意终止是终局。** 停止和租约过期后的 Run 不自动续跑，本机命令可能已产生副作用。

## 数据模型

- `conversation_assistant_workspaces` 增加 `approval_mode` 与 `allowed_command_prefixes jsonb`，修改由主人完成。Run 的行为快照记录领取时生效的模式与允许列表。
- 新表 `agent_run_approvals` 表达待确认请求：`organization_id`、`agent_run_id`、`tool_call_id`、能力组、命令或相对路径、`status`、`decided_by_user_id`、拒绝原因、时间戳，`(organization_id, agent_run_id, tool_call_id)` 唯一。决定在事务中写入并推进会话版本，提交后通知执行设备。
- `agents` 增加模型来源，本机 Agent 来源记录外部 Agent 种类；外部 Agent 的安装位置与登录状态只由设备本地探测。
- `devices` 的 `runtime_version` 与 `tool_manifest jsonb` 随只读本机工具批增加，本机 Agent 批在清单中上报已安装的外部 Agent；`trust_level` 与服务端 Agent 调用设备用的 `capability_manifest` 随 P2 增加。

## 派发与租约

- 本机前端对被同一工作区挡回的领取展示「等待同一工作区的其他任务完成」。
- 停止与租约失效时，除中断 Agent 循环外还要终止该 Run 启动的整个命令进程组或外部 Agent 进程。

## 运行时对齐

- 行为快照在领取时写入，工具清单取决于领取设备的能力清单、会话审批模式与触发者；快照写定后，重试落在不再提供这些工具的设备上时直接失败。
- 首版不加载配置版本绑定的企业远程 MCP 服务。

## 本机工具

首批工具由 `adk/middlewares/filesystem` 提供定义与提示词，Cervi 只实现两个接口。官方只提供内存后端，本地磁盘后端自行实现。

`workspaceBackend` 实现 `filesystem.Backend`：

- 所有路径先相对工作区根规范化，再经 `filepath.EvalSymlinks` 解析，解析后仍必须位于工作区内，`..` 或符号链接越出工作区的路径被拒绝。
- `GrepRaw` 用 Go 正则实现，工具描述改写为实际支持的语法，描述与实现保持一致。
- 实现 `MultiModalReader`，支持读取图片与 PDF。

`workspaceShell` 实现 `filesystem.Shell`：

- 工作目录固定为工作区根，以独立进程组启动。超时、取消和 Run 结束三条路径都终止整个进程组。
- 输出按字节上限裁剪并置 `Truncated`；命令预算由后端自己计时并置 `TimedOut`。
- 环境变量按白名单传递，不透传桌面进程的完整环境。
- 首版只在 macOS 与 Linux 注册命令执行工具；Windows 只提供文件工具，界面说明原因。

四个超时各自命名，互不复用：设备租约续期间隔、本地 Run 总时限、单次命令预算、单轮模型静默。

### 能力组与风险类别

能力在审批模式上按组表达，单个工具映射进组。已有组内增加工具不改配置与界面。

| 能力组 | 工具 | 风险类别 |
| --- | --- | --- |
| 文件读取 | `ls`、`read_file`、`glob`、`grep` | 只读 |
| 文件写入 | `write_file`、`edit_file` | 改本机状态 |
| 命令执行 | `execute` | 执行任意代码 |

每个工具携带声明的风险类别，审批中间件按类别、会话审批模式与触发者决定放行、确认或不提供，**没有声明类别的工具默认需要审批**。注册表覆盖测试断言每个工具都有类别，且其他成员触发的运行中不出现非只读工具。

### 工具扩展规则

- 设备在注册和启动时上报 `tool_manifest`，服务端按交集计算有效集，两侧未知的能力名一律丢弃。
- 服务端可为工具声明所需的最低设备运行时版本，低版本设备直接得不到该工具，不产生业务兼容分支。
- 审批中间件必须同时实现 `WrapInvokableToolCall` 和 `WrapEnhancedInvokableToolCall`。返回多模态结果的工具走 Enhanced 路径，只实现前者会让这类工具经基类直通默认实现而不触发审批。
- 启用后台命令时，后台任务生命周期绑定在 Run 上，Run 结束即终止。
- 工具总数使上下文中的工具定义成为负担时，改用 `adk/middlewares/dynamictool/toolsearch` 按需暴露。

## 本机 Agent 来源

助理背后是主人电脑上安装的外部编程 Agent（如 Codex、Claude Code、Gemini CLI），经 ACP 驱动，由外部 Agent 使用其官方登录与主人的订阅额度。

- 此来源的助理不走 `agentruntime`：Cervi 把会话输入交给外部 Agent，转发其权限请求到审批卡片，回写最终回复、过程摘要与变更摘要；输入认领、结果事务与群聊轮转仍在服务端。
- 外部 Agent 以该会话的工作区为工作目录启动。审批模式同样适用：外部 Agent 的权限请求按模式自动允许或转为审批卡片；其他成员触发时以外部 Agent 的只读模式启动，并拒绝其写入与命令请求。
- 设备在能力清单中上报已安装且可用的外部 Agent，编辑页只列出这些选项；外部 Agent 未登录时，助理回复需在电脑上完成登录。
- 各外部 Agent 的订阅是否允许经第三方客户端驱动，接入前逐个核实条款。

## 审批实现

- 审批中间件在工具执行前向服务端上报待确认请求并阻塞等待决定；设备经事件流唤醒读取决定，并按固定间隔补查。
- 审批决定、触发者、审批人、工具参数和裁剪后的结果写入 Run 内容块，随收尾回写服务端审计。

## 安全边界

- 首版不提供操作系统级沙箱，命令执行以主人审批、审批模式和工作区围栏为防线，残余风险明确承认。
- 设备认证是登录 Token 加设备编号加撤销位，挡不住 Token 泄露后的设备冒用。后续强化路径是设备密钥对与请求签名。
- 其他成员可以通过对话让助理读取并在群内输出工作区内容。主人为群选择工作区时明示群成员范围，确认即授权；不希望共享的内容不放进该工作区。
- 引入跨 Run 长期记忆时，每条记忆必须携带来源受众标签，只返回给同受众的运行。

## 交付批次

**只读本机工具。** `workspaceBackend`、工作区身份校验、路径围栏、能力清单上报与交集。验收：`..`、符号链接、已移动的工作区全部被拒；低版本设备得不到未支持的工具。

**审批与本机 Agent。** 审批记录与契约、任意端审批卡片与通知、会话审批模式与命令允许列表、审批中间件两条路径、决定入块；ACP 适配器、外部 Agent 探测与模型来源选择、变更摘要与本机差异查看。验收：主人在手机上允许后电脑继续执行；拒绝后模型能改方案重试；外部 Agent 的权限请求按审批模式处理；设备侧与服务端都不出现外部 Agent 的订阅凭据。

**内置写入与命令。** `workspaceShell`、进程组终止、写入与命令工具接入审批模式。验收：停止时命令进程组终止；多模态结果工具同样触发审批；允许列表不放行含管道、重定向或命令串联的命令。

**群聊中的助理。** 选择器只向主人列出其助理并在加入时选择工作区、群内的助理工作区与审批模式入口、群内展示「<主人>的助理 · <名称>」、成员范围提示与新增成员提示、其他成员触发时固定只读、等待确认状态展示、群主移出助理。验收：其他成员触发的运行不出现写入与命令工具；混有其他成员触发的输入窗口按只读执行。

界面操作（截图、鼠标与键盘输入）暂缓，出现明确场景后随 macOS 辅助功能与屏幕录制授权引导一起交付。

## 验收边界

- AI 员工只在服务端执行，助理只在绑定电脑上执行。
- 助理不出现在主人不在的会话和任何客户会话中。
- 停止后本机命令进程组与外部 Agent 进程终止。
- 设备侧不出现企业模型供应商凭据，服务端不出现工作区真实路径和外部 Agent 订阅凭据。
- 工作区外路径被拒绝。
- 其他成员触发的运行只有只读工具。
- 设备撤销后不能调用模型代理。
- 服务端与设备对同一 Run 解析出同一份有效配置。
- 未声明风险类别的工具不会被自动放行。

## 不做的事

操作系统级沙箱、外部编辑器经 ACP 调用 Cervi、移动端本地运行、设备端本地模型与离线运行、跨设备迁移进行中的 Run、唤醒或控制离线的电脑、其他成员邀请别人的助理进群、设备侧本地知识库。

## 未决

- 等待审批是否计入本地 Run 总时限，以及长时间无人处理时的结束方式。
- 设备侧运行时崩溃与桌面端主进程崩溃的区分上报方式。
- Windows 命令执行的进程组方案与开启条件。
- 附件在设备与模型代理之间的二次搬运是否需要由代理直接注入。
