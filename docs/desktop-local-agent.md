# Cervi 助理与桌面端本地运行实施方案

状态：实施中  
日期：2026-09-23  
范围：助理（成员本人创建、绑定自己电脑的 AI）的产品形态、交互与桌面端本地运行（P4）  
关联：本文是 [Cervi 路线图](roadmap.md) 登记的独立方案，设计细节只保留在本文；助理与 AI 员工在工作台中的展示位置见 [工作台信息架构与服务对象扩展方案](workbench-ia.md)

成员在自己的电脑上创建助理，助理在主人的电脑上查阅和整理资料、修改文档与表格、改代码，并可以通过对话安装和使用技能。助理默认使用企业模型服务，开箱即用；电脑上已装好支持 ACP 的 Agent（如 WorkBuddy、Codex、Claude Code）的成员，可以让助理交给它完成。主人可以在任意端和助理对话；把助理带进群里后，群成员都可以让它在主人的电脑上工作。本文是主要参考，不构成强制约束，实施中按更合适的做法调整并同步更新；已交付的部分以代码为准，本文只保留后续批次的设计，全部交付后连同路线图中的对应条目一并删除。

## 产品定义

### 定位

助理面向企业里的普通成员，不要求使用者懂技术。它的价值是把「让 AI 在我电脑上干活」放进协作会话：任务从聊天发起，过程和结果留在会话里，同事可以在群里请主人的助理帮忙。

- 默认使用内置运行时与企业模型服务，成员不需要安装或登录任何额外工具。
- 主人电脑上已有支持 ACP 的本机 Agent 时，可以改由它完成工作。本机 Agent 不限于编程，办公类 Agent 同样适用。

### 两类 AI

| | AI 员工 | 助理 |
| --- | --- | --- |
| 归属 | 企业，由管理员创建 | 成员本人创建，一个成员可以有多个 |
| 执行位置 | 服务端 | 只在主人绑定的那台电脑上 |
| 操作电脑 | 不能 | 能 |
| 模型 | 企业模型服务 | 企业模型服务，或主人电脑上的本机 Agent |
| 在线 | 始终可用 | 绑定的电脑在线且未暂停 |
| 服务会话 | 可以接待客户、员工、伙伴 | 不能接待，与助理的对话不产生服务周期 |
| 内部单聊与群聊 | 可以 | 只进入主人所在的会话 |
| 通讯录 | 不列入；服务对象含本企业员工的以服务台列在同事中 | 挂在主人名下展示 |

执行位置由归属决定：AI 员工永远在服务端执行，助理永远在主人的电脑上执行。同一个 AI 不会因为触发者或会话不同而切换模型来源或执行位置。

### 命名与界面用词

界面统一称「助理」，展示为「<主人姓名>的助理 · <助理名称>」，例如「张三的助理 · 小码」。英文界面使用 `Assistant`。

过程展示用白话描述助理在做什么，命令原文、完整参数等技术细节折叠在「详情」中。本机 Agent 以产品名展示，例如「由电脑上的 WorkBuddy 完成」。

### 助理跟随主人

助理在主人的电脑上执行、动的是主人的文件，因此：

- 助理只出现在主人所在的会话中。其他成员不能与别人的助理单聊，只能在主人也在的群里使用它。
- 只有主人能把自己的助理加入群聊。
- 主人退出群聊时，其名下助理同时退出该群。
- 主人被停用时，其名下助理全部停用并退出所有群聊；主人恢复后助理保持停用，由主人重新启用。
- 助理不能接待客户，也不能被加入客户会话。

成员都可以创建助理，企业不设总开关；管理员可以停用单个助理。

## 交互

### 创建、管理与在线状态

助理的创建、编辑、换电脑、暂停、停用与在线状态已在桌面端和 Web 端上线，剩余：

- 头像上的在线状态标记：在线绿点、离线灰色、暂停标记；目前在线状态以文字展示在列表与会话头。
- 编辑页的「由谁完成」选项：只在绑定电脑上探测到可用的本机 Agent 时出现，默认由助理自己完成，随「本机 Agent」批次交付。

### 单聊

- 在绑定电脑上实时展示运行过程；其他端展示运行状态与最终回复。

### 默认文件夹

- 每个会话在绑定电脑上有一个默认文件夹，位于用户文档目录（macOS 为「文稿」，Windows 含 OneDrive 重定向后的位置，Linux 按 XDG 用户目录）下的 Cervi，首次运行时自动创建，创建失败只影响文件工具；主人参与该会话的助理共用。它是命令的工作目录，也是生成文件的默认位置。
- 不单独指定文件夹：用户在对话中提到哪个文件夹，助理就去哪里工作。文件工具使用电脑上的真实路径，相对路径以默认文件夹为起点。

### 群聊

- 群成员选择器中，主人能看到并添加自己的助理；其他成员看不到别人的助理。
- @ 助理与 @ AI 员工交互一致，群成员都可以触发助理，能力与主人触发相同。助理之间、助理与 AI 员工之间按现有轮次规则接力，各助理在各自主人的电脑上执行。
- 主人可以随时把自己的助理移出任何群，群主可以移出群内任何助理。

### 各端差异

| | 绑定电脑上的桌面端 | 其他桌面端 | Web 与移动端 |
| --- | --- | --- | --- |
| 创建、换电脑 | 可以 | 可以（换到这台电脑） | 不可以 |
| 与助理对话 | 可以 | 可以 | 可以 |
| 运行过程 | 实时流式 | 状态与最终回复 | 状态与最终回复 |

## 架构

```text
服务端
├── 发送事务与群聊轮转：助理的 Run 写入执行设备（助理绑定电脑），不投递服务端任务
├── 设备工作通知：提交后经成员事件流推送 device_work_advanced
├── 领取与续租：设备领取 Run 并取得租约，续租响应回带取消状态
├── 运行期服务：Peek／Claim 读取 Lane 输入、知识检索、附件读取
├── 模型代理：校验 Run、设备与租约后注入供应商凭据并透传流式响应
└── 收尾：result 与 failure 两个入口进入既有结果事务，群聊在同一事务提取点名并轮转

桌面端 Go
├── 设备注册与领取循环：独立定时器加事件流唤醒
├── agentruntime：与服务端同一份代码，用于企业模型服务来源
├── ACP 适配器：驱动本机 Agent
├── 远程适配器：InputFeed、知识检索、附件读取、模型 BaseURL 指向服务端代理
├── 本机工具：localworkspace 提供本机文件读写与命令执行
├── 技能：本机技能目录，运行时按需加载
└── 本机运行流：本机界面查看本机执行中的运行时直接订阅本机过程流
```

## 不变量

- **执行位置由归属决定。** AI 员工的 Run 只在服务端执行，助理的 Run 只派发到助理绑定的电脑。
- **运行时同一份。** 企业模型服务来源的助理与服务端执行同一份 `internal/integration/agentruntime` 代码，有效配置由同一个解析器 `ResolveAssignment` 产出。执行侧能力只影响工具清单、指令中的工具说明和 MCP 服务名称。
- **业务事实只在服务端。** Run、Lane、Input、内容块、结果消息幂等和群聊轮转全部在服务端事务内完成，设备本地只保存设备注册。
- **企业凭据不下发。** 使用企业模型服务时，设备取得的配置不含模型凭据，模型调用经服务端代理。
- **订阅凭据不上行。** 本机 Agent 的登录与订阅凭据只由其自己管理，Cervi 不读取、不保存、不上传。
- **文件位置由设备决定。** 默认文件夹位于用户文档目录下的 Cervi，按会话编号命名，服务端不保存其位置；运行过程中访问过的路径与读取结果随过程内容回写，会话成员都能查看。
- **助理跟随主人。** 助理只作为参与者存在于主人所在的会话，主人离开即随之离开。
- **本机工具全部提供。** 设备执行的运行提供本机工具目录中的全部工具，桌面端与服务端随同一版本发布，不做版本协商。
- **同一默认文件夹同一时刻只有一个运行。** 服务端按执行范围限定排队中与运行中的 Run 最多一个，单聊与群聊的执行范围即会话，同一会话的助理不会同时改动默认文件夹。
- **有意终止是终局。** 停止和租约过期后的 Run 不自动续跑，本机改动可能已经发生。

## 数据模型

- `agents` 增加由谁完成：助理自己或本机 Agent，后者记录其种类；本机 Agent 的安装位置与登录状态只由设备本地探测。
- 「本机 Agent」批由设备上报电脑上已安装且可用的本机 Agent，供编辑页列出选项。`trust_level` 与服务端 Agent 调用设备用的 `capability_manifest` 随 P2 增加。

## 派发与租约

- 停止与租约失效时，除中断 Agent 循环外还要终止该 Run 启动的本机 Agent 进程及其子进程。

## 运行时对齐

- 行为快照在领取时写入。
- 本地 Run 当前不加载配置版本绑定的企业远程 MCP 服务，随「企业 MCP 与群聊中的助理」批次加载。

## 本机工具

### 运行环境

- 桌面端提供由 Cervi 管理的 `uv`（管理 Python 解释器与依赖）与官方 Node.js（含 `node`、`npm`、`npx`），不打进安装包，登录后由设备在后台下载。其他缺少的工具由助理在对话中自行安装。
- 版本在构建时固定：`uv` 与 Node.js 各平台发行物的版本与 SHA256，以及默认 Python 的精确版本。下载由 Go 侧统一执行，校验通过后原子移入正式目录；默认 Python 由 `uv python install <版本> --default --no-registry` 安装。
- 运行环境准备是设备级后台任务，与 Run 分离，不占用 Run 租约；下载失败由设备退避重试。首次准备完成前设备不领取 Run，Run 在服务端保持排队；之后的版本升级在后台准备，完成后切换，不阻塞领取。准备进度与失败原因只在这台电脑的桌面端展示。
- 工具链放在用户级目录，避开 macOS `Application Support` 路径中的空格；不随 `DESKTOP_DATA_DIR`、`XDG_DATA_HOME`、`XDG_CACHE_HOME` 变化，同一操作系统用户的所有企业共用：

  | 内容 | macOS / Linux | Windows |
  |---|---|---|
  | 工具链根目录 | `~/.local/share/cervi/toolchains/` | `%LOCALAPPDATA%\cervi\toolchains\` |
  | 下载与包缓存 | `~/Library/Caches/cervi/`（Linux 为 `~/.cache/cervi/`） | `%LOCALAPPDATA%\cervi\cache\` |

- 工具链根目录下，发行物与安装内容分开存放：

  ```text
  toolchains/
  ├── dist/uv/<版本>/       uv 发行物，升级时整体替换
  ├── dist/node/<版本>/     Node.js 发行物，升级时整体替换
  ├── python/               Python 解释器（UV_PYTHON_INSTALL_DIR）
  ├── uv-tools/             uv tool 环境（UV_TOOL_DIR）
  ├── npm-global/           npm 全局包（NPM_CONFIG_PREFIX）
  └── bin/                  python 命令与 uv tool 命令（UV_PYTHON_BIN_DIR、UV_TOOL_BIN_DIR）
  ```

  升级只替换 `dist/` 下的版本，当前版本记录在设备本地，旧版本在没有命令使用时清理；`python/`、`uv-tools/`、`npm-global/`、`bin/` 跨升级保留。默认 Python 版本变化时只安装新版本并切换 `--default`，已安装的解释器不自动删除：虚拟环境与 uv tool 环境按具体路径引用解释器。
- 命令执行时依次把 `dist/uv/<当前版本>`、Node.js 可执行文件目录（Unix 为 `dist/node/<当前版本>/bin`，Windows 为版本目录本身）、`bin/` 与 npm 全局命令目录（Unix 为 `npm-global/bin`，Windows 为 `npm-global` 本身）前置到 `PATH`，系统原有路径保留在后，其他工具照常可用。
- 命令执行的环境变量把安装与缓存限定在上述目录：`UV_PYTHON_PREFERENCE=only-managed`、`UV_PYTHON_INSTALL_DIR`、`UV_PYTHON_BIN_DIR`、`UV_PYTHON_INSTALL_REGISTRY=0`、`UV_TOOL_DIR`、`UV_TOOL_BIN_DIR`、`UV_CACHE_DIR`、`NPM_CONFIG_PREFIX`、`NPM_CONFIG_CACHE`。
- 下载源可替换为镜像，覆盖 `uv` 与 Node.js 发行物、Python 解释器（`UV_PYTHON_INSTALL_MIRROR`）、PyPI（`UV_DEFAULT_INDEX`）与 npm（`NPM_CONFIG_REGISTRY`），默认值由当前企业服务端下发。镜像只在当次命令的环境变量中注入，不写入工具链目录中的 `uv.toml`、`.npmrc` 等共用配置。
- 不复用、不修改电脑上已有的 Python 与 Node，不改 shell 配置、系统 `PATH` 与 Windows 注册表。Cervi 创建的环境只使用托管解释器。唯一例外是用户项目已有的 `.venv` 与 `.python-version`：它们属于项目自身环境，按 `uv` 的规则使用。
- 删除工具链根目录与缓存目录即清除 Cervi 管理的运行时；用户项目中的 `.venv` 不在其内。

### 技能

- 技能标准与接入方式见路线图「Skills」。技能安装在主人的电脑上：Cervi 在应用数据目录中维护一个本机技能目录，这台电脑上主人的所有助理共用；主人在对话中让助理安装技能，助理把技能包下载到该目录。服务端不保存技能。
- 技能中的脚本经命令执行运行，Python 依赖由助理借助 `uv` 安装，JavaScript 依赖借助 `npm` 安装。Word、Excel、PPT 等 Office 文件的读取与改动由对应技能的脚本完成，不单独开发 Office 工具。

### 工具扩展规则

- 启用后台命令时，后台任务生命周期绑定在 Run 上，Run 结束即终止。
- 增加单轮模型静默超时时单独命名，不复用设备租约续期间隔、本地 Run 总时限与单次命令预算。

## 本机 Agent

助理背后是主人电脑上安装的、支持 ACP 的 Agent，包括办公类（如 WorkBuddy）与编程类（如 Codex、Claude Code、Gemini CLI），由其使用自身的登录与主人的订阅额度。

- 此来源的助理不走 `agentruntime`：Cervi 把会话输入交给本机 Agent，回写最终回复与过程摘要；输入认领、结果事务与群聊轮转仍在服务端。
- 本机 Agent 以会话的默认文件夹为工作目录启动，其权限请求一律自动允许；它使用自身安装的技能，不读取 Cervi 的本机技能目录。
- 设备上报已安装且可用的本机 Agent，编辑页只列出这些选项；本机 Agent 未登录时，助理回复需在电脑上完成登录。
- 各本机 Agent 的订阅是否允许经第三方客户端驱动，接入前逐个核实条款。

## 交付批次

**Skills。** `uv` 与 Node.js 运行环境的后台准备，本机技能目录与技能加载。验收：不做任何设置，在对话中让助理安装一个 Office 技能后，它能生成或修改表格与文档；电脑上已有的 Python、Node 与 shell 配置不受影响。

**企业 MCP 与群聊中的助理。** 本地 Run 加载企业远程 MCP 服务；选择器只向主人列出其助理、群内展示「<主人>的助理 · <名称>」、群主移出助理。验收：助理在本机运行时能调用企业 MCP 工具；群成员 @ 助理后，助理在主人电脑上完成任务并在群内回复。

**本机 Agent。** ACP 适配器、本机 Agent 探测与编辑页「由谁完成」选项、本机 Agent 的过程与最终回复回写。验收：本机 Agent 能完成任务并回复；停止时本机 Agent 进程终止；设备侧与服务端都不出现本机 Agent 的订阅凭据。

界面操作（截图、鼠标与键盘输入）暂缓，出现明确场景后随 macOS 辅助功能与屏幕录制授权引导一起交付。

改动前确认、群成员的权限区分、可访问文件范围、操作系统级沙箱与设备密钥签名等安全能力，准备正式上线时随安全专项统一设计。

## 验收边界

- AI 员工只在服务端执行，助理只在绑定电脑上执行。
- 助理不出现在主人不在的会话和任何客户会话中。
- 停止后命令进程组、本机 Agent 进程及其子进程终止。
- 设备侧不出现企业模型供应商凭据，服务端不出现本机 Agent 订阅凭据。
- 相对路径与命令工作目录都以会话的默认文件夹为准。
- 设备撤销后不能调用模型代理。
- 服务端与设备对同一 Run 解析出同一份有效配置。

## 不做的事

外部编辑器经 ACP 调用 Cervi、移动端本地运行、设备端本地模型与离线运行、跨设备迁移进行中的 Run、唤醒或控制离线的电脑、其他成员邀请别人的助理进群、设备侧本地知识库。

## 未决

- 设备侧运行时崩溃与桌面端主进程崩溃的区分上报方式。
- 附件在设备与模型代理之间的二次搬运是否需要由代理直接注入。
- 本机 PDF 的读取方式：模型输入模态尚无 PDF，`read_file` 目前只按图片读取 PNG、JPEG、GIF、WebP。
